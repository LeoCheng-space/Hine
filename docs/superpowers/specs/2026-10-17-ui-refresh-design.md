# HINE UI 改版設計（Telegram 式手感，HINE 品牌）

- 日期：2026-10-17
- 分支：`feature/ui-refresh`
- 狀態：設計已由使用者逐段確認，待撰寫實作計畫
- 範圍：僅前端（`frontend/app/`）與 CI 瀏覽器驗收腳本（`tests/browser/browser_acceptance.py`）；不變更 REST、WebSocket 事件、資料庫或 migration

## 1. 目標與決策

使用者認為現行 UI「有點簡易、比較沒有流暢性」，希望參考 Telegram 的版面與操作手感，但保留 HINE 自己的風格。已確認的決策：

| 項目 | 決定 |
|---|---|
| 參考對象 | Telegram 的版面與互動手感，不照抄外觀 |
| 品牌 | 沿用現有 HINE 品牌並精緻化：深青綠主色、H 對話泡泡標誌、標語「讓每一次對話，更靠近。」 |
| 主要裝置 | 桌面優先；手機（<768px）維持好用但不做完整精修 |
| 範圍方案 | 方案 A：視覺與動畫、對話清單改版、聊天室改版、☰ 側邊選單、建立群組改為勾選聯絡人；個人檔案／聯絡人／群組管理維持獨立頁面，只換外觀 |
| 不做 | 深色模式、側邊滑出面板（個人檔案／聯絡人／群組資訊）、自動載入較早訊息、任何後端或 API 變更 |

## 2. 必須保留的既有行為

改版只改外觀、排版與前端導覽方式，以下行為與其資料流不得改變：

- 網址路由與權限檢查：`/login`、`/register`、`/chats`、`/chats/{id}`、`/contacts`、`/profile`、`/groups/{id}/manage`。
- 單一操作分頁鎖（Web Lock）、工作階段刷新與登出流程、能力不足時的阻擋畫面。
- 768px 單一斷點（767 以下為手機版面）。
- 輸入：Enter 傳送、Shift+Enter 換行、Ctrl／⌘+Enter 傳送、中文輸入法組字中按 Enter 不送出、文字 1–4096 code points。
- 已讀判定（他人訊息可見 50% 且連續 500ms）、遮罩／隱藏時不已讀；`data-message-id`、`data-read-eligible`、`data-read-occlusion` 屬性與 `ReadObserver` 不變。
- 草稿保存、捲動錨點、「載入較早訊息」與「跳至最新」的歷史邏輯、原意圖重試、撤權撤離、附件上傳與核對流程。
- 未讀數只取伺服器回傳值；群組不顯示已讀人數。
- 建立群組的冪等鍵、原意圖保存與核對流程（`GroupCreationIntentStore`）。

## 3. 視覺系統

### 3.1 配色

以 HINE 主色 `#1b6558` 延伸色階，集中定義為 CSS 自訂屬性（design tokens），所有元件只引用 token：

| Token 用途 | 說明 |
|---|---|
| 主色與色階 | `#1b6558` 為基準的 50–900 色階；主要按鈕、未讀徽章、已讀勾勾、選取狀態 |
| 自己的泡泡 | 淺青綠（主色色階淺端） |
| 對方的泡泡 | 白色 |
| 聊天背景 | 淺灰綠，加上極低對比、以 CSS 產生的 H 泡泡圖樣（不新增圖檔） |
| 文字 | 主要文字 `#18312e`、次要文字沿用 `--muted` |
| 錯誤 | 沿用 `#a62d3b` |
| 頭像／群組寄件者名稱色 | 6 種與品牌相容的顏色，依使用者 ID 固定分配 |

所有文字與背景組合對比度至少 4.5:1。

### 3.2 品牌元素

- 訊息泡泡圓角 16px，自己的泡泡右下角、對方的泡泡左下角收尖為 4px，呼應 H 標誌「一角收尖」的對話泡泡造型；連續訊息只有該組最後一則收尖。
- 未選擇對話時，右欄顯示 H 標誌與標語「讓每一次對話，更靠近。」。
- 登入、註冊、多分頁阻擋與能力不足畫面改用同一套品牌樣式。

### 3.3 字型、間距、動態

- 字型沿用 Inter＋Noto Sans TC。清單名稱 15px／600、預覽 14px 次要色、時間 12px。
- 間距採 4px 倍數。
- 動態 token：150ms 與 220ms，緩出曲線；`prefers-reduced-motion: reduce` 時關閉所有過場與動畫。

## 4. 版面與導覽

### 4.1 桌面（≥768px）雙欄

- **左欄**：寬度約 340px（300–400px）。頂部為 ☰ 按鈕與搜尋框；下方為對話清單；右下角 ✎ 浮動按鈕開啟「建立群組」。
- **右欄**：聊天室；未選對話時顯示品牌空畫面。
- **☰ 側邊選單**：自左側滑出的抽屜。頂部顯示自己的頭像與名稱；項目依序為「個人檔案」「聯絡人」「建立群組」「登出」。按 Esc、點遮罩或選擇項目後關閉，焦點回到 ☰。
- **聯絡人、個人檔案、群組管理**：維持獨立路由頁面，佔滿內容區，左上角「← 返回聊天」，套用新視覺。

### 4.2 手機（<768px）

- 單欄；對話清單與聊天室以水平滑動過場切換。
- ☰ 側邊選單以覆蓋層呈現。
- 群組資訊對話框須完整落在 390×844 視窗內（既有驗收條件）。

## 5. 對話清單

### 5.1 每列內容

| 項目 | 規則 | 資料來源（既有） |
|---|---|---|
| 頭像 | 有頭像顯示頭像；否則為名字首字圓形，底色依 ID 固定分配；一對一對象在線時加綠點 | 使用者摘要、`presence` |
| 名稱 | 一對一為對方顯示名稱；群組為群組名 | 對話詳情成員＋使用者摘要 |
| 預覽 | 最後一則訊息單行截斷；自己的訊息前綴「你：」；群組他人訊息前綴「名稱：」；圖片為「📷 圖片」、檔案為「📄 檔案」 | `ChatSnapshot.messages[id]` 最後一則 |
| 時間 | 今天 `HH:mm`；昨天「昨天」；7 天內「週一」等；更早 `M/D`；跨年 `YYYY/M/D` | 最後訊息 `created_at` |
| 未讀 | 主色圓形徽章，0 不顯示 | A11 `unread_count`（語義不變） |

### 5.2 排序、搜尋、載入

- 依最後一則訊息時間由新到舊；本機尚無訊息的對話排在後面，維持伺服器回傳順序。清單分頁不變，「載入更多」保留於底部。
- 搜尋框比對已載入對話的名稱與預覽文字，並明示「只搜尋已載入的對話」，不是全站搜尋。
- 一對一名稱需要對話成員與使用者名稱：只在清單列出現時才取得（A12 詳情、A07 使用者摘要），限制同時請求數並依 `membership_version` 與使用者 ID 快取。取得失敗時顯示 ID，不阻擋清單。
- 載入中顯示骨架列；沒有對話時顯示插圖與「到聯絡人開始聊天」「建立群組」兩個按鈕。

## 6. 聊天室

### 6.1 頂部列

- 頭像＋名稱。副標題：一對一在線時顯示「線上」，否則不顯示；群組顯示「N 位成員」。
- 連線狀態非 ready 時，副標題改為對應狀態，例如「連線中…」或「離線，訊息會在恢復後送出」。
- 群組右側為群組資訊圖示按鈕，無障礙名稱維持「群組資訊」，開啟既有群組資訊對話框。

### 6.2 訊息

- **分組**：同一寄件者 5 分鐘內的連續訊息為一組；組內間距縮小，只有最後一則收尖。
- **群組寄件者**：每組第一則顯示寄件者名稱（依 ID 固定配色），最後一則旁顯示寄件者頭像。
- **日期分隔**：置中膠囊「今天／昨天／10月15日」，捲動時固定於上方。
- **時間與狀態**：泡泡右下角顯示時間；自己的訊息加狀態，並附無障礙文字：

| 狀態 | 圖示 |
|---|---|
| 等待傳送 | 🕓 |
| 伺服器已保存 | ✓ |
| 已送達 | ✓✓（灰） |
| 已讀（僅一對一） | ✓✓（主色） |
| 結果不明／失敗 | ⚠，並保留既有「以原意圖重試」 |

- **新訊息出現**：淡入並上移 8px，150ms。
- **附件**：圖片以圓角縮圖置於泡泡內；檔案為圖示＋檔名＋大小卡片；既有附件預覽對話框套用新外觀。

### 6.3 捲動與輸入

- 「跳至最新」改為右下角圓形 ↓ 按鈕並顯示新訊息數（沿用既有計數，非未讀數）。
- 「載入較早訊息」保留按鈕，改為頂部小膠囊；不改為自動載入。
- 輸入列：左側 📎（選取附件），中間圓角輸入框自動增高至約 6 行，右側圓形 ➤ 傳送鈕（無內容時停用）；字數計數超過 3,800 字才顯示。鍵盤規則不變（見第 2 節）。

## 7. 建立群組

由 ✎ 浮動按鈕或 ☰ 選單開啟對話框，分兩步：

1. **選成員**：搜尋框＋聯絡人清單（頭像、名稱、勾選框，支援「載入更多」）；已選成員以可移除標籤顯示於頂部，標示「已選 N／49」，達上限時停用勾選。另有「以公開 ID 加入」欄位：輸入 ID 後以 A07 查詢並顯示名稱，確認後加入。
2. **群組名稱**：輸入名稱後按「建立群組」，成功後開啟該群組。

建立邏輯沿用 `GroupCreationIntentStore`：送出內容 `{title, member_ids}`、冪等鍵、結果不明時「以原意圖重試／核對」與「已核對結果，結束原意圖」、重新整理後還原未完成意圖；有未完成意圖時鎖定名稱與成員。群組名稱不得為空，其餘規則由伺服器判定。

## 8. 無障礙

- ☰ 側邊選單與所有對話框：開啟後焦點限制於其中，Esc 關閉，焦點回到觸發按鈕；沿用群組資訊對話框的實作模式。
- 純圖示按鈕皆有無障礙名稱，例如「開啟選單」「建立群組」「選取附件」「傳送」「跳至最新」「群組資訊」。
- 訊息狀態圖示附文字（「已讀」「已送達」等）。
- 鍵盤焦點外框清楚可見；觸控目標至少 44px；保留「跳至主要內容」連結。

## 9. 元件與檔案

| 單元 | 職責 |
|---|---|
| 設計 token（`Shell.css` 開頭） | 色彩、字級、圓角、陰影、動態時間；元件只引用 token |
| 外殼與導覽（`App.tsx`） | 雙欄外殼、☰ 側邊選單、手機單欄切換、品牌空畫面 |
| 對話清單（自 `App.tsx` 拆出 `ChatList.tsx`） | 列資料推導、排序、搜尋、骨架與空狀態 |
| 清單／訊息純邏輯（新 `chat-presentation.ts`） | 預覽文字、時間格式、排序、訊息分組、日期分隔、狀態對應、頭像配色；不依賴 React，可單元測試 |
| 聊天室（`ChatView.tsx`、`Chat.css`） | 頂部列、泡泡、分組、日期分隔、輸入列、↓ 按鈕 |
| 建立群組（`GroupsPage.tsx` 的 `CreateGroup`） | 兩步對話框、聯絡人勾選、以公開 ID 加入 |
| 其他頁面（`AccountPages.tsx`、`ContactsPage.tsx`、`ProfilePage.tsx`、`GroupsPage.tsx`、`AttachmentViewer.tsx`） | 套用新視覺，行為不變 |
| CI 驗收（`tests/browser/browser_acceptance.py`） | 依新導覽與建群組流程更新操作步驟，不放寬任何檢查 |

## 10. 測試與驗證

1. 測試先行：`chat-presentation.ts` 的預覽、時間格式、排序、分組、日期分隔、狀態對應、頭像配色；建群組的選取上限與送出內容。
2. 既有前端測試全數通過，typecheck 與正式建置通過。
3. 更新 CI 瀏覽器驗收腳本的導覽與建群組步驟；以 GitHub Actions 的 Chrome／Edge 驗收實際通過為準。與已移除元素綁定的檢查（例如手機版「主要導覽」列需固定於畫面）改為檢查取代它的新元素並維持同等要求（例如手機頂部列固定、☰ 選單可用），不得刪除或降低檢查。
4. 本機 Docker 實測：以臨時帳號操作一對一、三人群組、建群組、側邊選單、附件錯誤提示與鍵盤操作；於 1280px 與 767／768px 截圖確認；完成後刪除臨時帳號並停止容器。
